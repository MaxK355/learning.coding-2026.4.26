It's Mooin' Time IV

Two keys and a virus. M appends M; O flips every letter already on screen. Can Bessie type a target string of M and O? Yes — always — and there is exactly one way to do it.

always YES unique keystrokes O(N) per test
the smallest sample
keys O M O → screen M O O
The mechanic

Two keys, one rule that looks backwards

M appends an M. O flips every letter already on screen, then appends an O. The O you press is never flipped by its own keystroke.

M · append

OM press M → OMM

An M lands at the end. Nothing already on screen moves.

O · flip, then append

OM press O → MOO

Every earlier letter flips M↔O. Then a fresh, unflipped O lands.

forward lab · press the keys and watch the screen
keys none yet

A letter flips once per later O. An O typed before it never touches it.

The key you press is not the letter that stays. A later O can rewrite letters already on screen.

The task

What the judge asks

Read the target, decide whether it can be typed, and — when asked — print the keys. The sum of all N is at most 4·105.

Input

The first line is T k, not just T. k is 0 or 1 for the whole run.

Each test then gives N and a string S of M and O.

Σ N ≤ 4·105 · use fast I/O with that many characters

Output

Always YES: every target is reachable. With k = 0 that one line is the whole answer.

First instinct · rejected

  
Why not just search?

  
Each keystroke is M or O, so there are 2N keystroke strings of length N. Simulating one is cheap. Trying all of them is not.

  

    

    
2400000 is about 10120412 — more strings than there are atoms in the observable universe.

  

  

    
The simulation has to be inverted, not searched. Track one number per position instead of every whole string.

  







  
Insight 01

  
Only later O's touch a letter

  

    

      
Fix a position. The letter typed there is flipped once by every O typed after it. O's typed before it never affect it, and its own keystroke never flips it.

      
So the final letter is the typed letter, XOR the parity of the number of later O's.

      

        
In the keys O M O, the only O after positions 1 and 2 is the one at position 3. It flips both of them once. Position 3 stays as typed, turning O M O into M O O.

      

    

    
  







  
Insight 02

  
The pressed letter cancels out

  
Let P be the total number of O keystrokes, and qj the number of O's typed before position j. Then an O at position j has exactly P − qj later O's behind it.

  

    
M   0 ⊕ (P − qj)≡ P − qj

    
O   1 ⊕ (P − qj − 1)≡ P − qj

    
With key M, the typed letter is 0. With key O, the typed letter is 1 but that same O also adds one to the count — the two cancel modulo 2.

  

  

    
The final string depends only on where the O's sit in the key sequence — not on which key is supposed to have produced each position.

  






  
Insight 03

  
Parity pins the O-count

  
Read the formula backwards. Position 1 gives P ≡ S1, so substituting into Sj ≡ P − qj gives qj ≡ S1 + Sj (mod 2). The parity of the count is fixed by the target.

  
The count starts at q1 = 0 and can only stay or rise by one. A rise flips the parity; a stay does not. So the count rises exactly where the target changes letter — the staircase is forced, with no choice left.

Insight 04

  
The last key is the last letter

  
One value is still open. After the final position the count becomes P = qN + cN, where cN is the final key. We need P ≡ S1, and qN ≡ S1 + SN, so the only key that works is cN = SN.

  
In plain letters: the last keystroke equals the last target letter. The one remaining bit of freedom is spent by the parity equation.


  

    

      
OOMOO · last key, resolved

      
qN = 2  ·  S1 = 0  →  P must be odd

      

        

          P = 2 + 0 = 2
          
EVEN · rejected

        

        

          P = 2 + 1 = 3
          
ODD · last key O

        

      

      
Only one of the two last keys matches the parity. The target picks it.

    


    

      
The rule

      
For j < N: press O exactly when Sj ≠ Sj+1; otherwise press M. The last key is cN = SN.

Your solution

  
The same idea, scanned backwards

  
The accepted solution keeps the parity of O keys already chosen to the right. At each position it undoes those flips, records the key, and if the key is O adds one flip for everything further left.

Summary

  
Three moves, one answer

  

    

      
① Invert the flip

      
Only later O's touch a letter. The final letter is the typed letter XOR the parity of later O's.

    

    

      
② The staircase is forced

      
qj ≡ S1 + Sj (mod 2). The count rises exactly where the target changes letter.

    

    

      
③ Copy the last letter

      
The last key is SN. Every other key follows a boundary. Exactly one sequence works.

    

  

  

    

      cj = O  ⇔  Sj ≠ Sj+1   ·   cN = SN
